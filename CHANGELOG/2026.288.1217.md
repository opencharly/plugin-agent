# 2026.288.1217 — docs: name this repo's own tui skill at its real address

## Summary

**This repo's own rulebook named the wrong address for its own skill.** `AGENTS.md` and `README.md` both pointed at `/charly-automation:tui`. The `tui-skill:` entity declares `family: agent`, and the corpus publishes it there, so the real address is `/charly-agent:tui` — while `automation` has no `tui` skill at all, so the old address resolved to nothing on every harness. A session loading this rulebook lost the skill silently, and a harness that cannot resolve it falls back by path to `automation/skills/tui`, which does not exist either.

Both sides, measured on the commit:

```
$ git show HEAD:candy/plugin-agent/charly.yml | sed -n '33,37p'

    skill:
        name: tui
        family: agent
        owner: plugin-agent

$ test -e marketplace/automation/skills/tui && echo "automation/skills/tui exists" || echo "automation/skills/tui: no such skill"
automation/skills/tui: no such skill

The generated dispatcher already agreed (`DISPATCHER.md:4` → `/charly-agent:tui`), so the rulebook was the one surface out of step.

**Fixed as an address class, not as a line.** Every `/charly-<family>:<skill>` address these two files cite was checked against the published corpus:

```
$ for a in $(grep -oh '/charly-[a-z0-9-]*:[a-z0-9-]*' AGENTS.md README.md | sort -u); do
    fam=${a#/charly-}; fam=${fam%%:*}; sk=${a##*:}
    test -f "$UMB/marketplace/$fam/skills/$sk/SKILL.md" && echo "  OK    $a" || echo "  WRONG $a"
  done
  OK    /charly-agent:tui
  OK    /charly-automation:agent
  OK    /charly-automation:tmux
  OK    /charly-internals:git-workflow
  OK    /charly-internals:plugin
```

and the wrong address is gone from every current surface, surviving only in history:

```

That one is `CHANGELOG/2026.271.2242.md`, which is history: history lives in `CHANGELOG/` and is not rewritten.

Closes #9.
